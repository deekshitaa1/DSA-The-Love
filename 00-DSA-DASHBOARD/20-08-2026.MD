## Complexity Awareness

While solving today's problems, I focused on identifying:

## Mistakes / Things To Improve

- Be careful with array boundaries and indexing.
- Check duplicate and empty-input cases.
- Avoid unnecessary nested loops when a lookup-based approach is possible.
- Always test the solution with more than one example.

---

## Interview Perspective

If an interviewer gives me an Array problem, I should:

1. Understand the input and expected output.
2. Clarify edge cases.
3. Explain the brute-force approach if relevant.
4. Look for a better pattern or data structure.
5. State time and space complexity.
6. Code clearly.
7. Dry-run the solution with an example.
